# PhysioBand AI

**Intelligent Resistance Exercise Quality Monitoring System** - final-year engineering project.

A wearable (2 x MPU6050 + S-type load cell + HX711 + ESP32) streams upper-arm movement, forearm movement and
resistance-band tension over BLE to a React Native app. A FastAPI backend runs the Python ML pipeline to count
repetitions and classify movement quality, stores everything in MongoDB Atlas, and the app shows live feedback,
results and history. The first supported exercise is the **Biceps Curl**.

> Training feedback only - not a medical device, no clinical diagnosis, no guaranteed injury prevention.
> The included AI model is a **demo trained on synthetic data** and is not validated (see `docs/ML_PIPELINE.md`).

## Quick start (Windows PowerShell)

### 1. Backend

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env        # then edit MONGODB_URI and JWT_SECRET_KEY
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Open http://localhost:8000/docs (Swagger) and http://localhost:8000/health.

### 2. ML (optional - a demo model is already in `ml/saved_models`)

```powershell
cd ml
..\backend\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts\generate_synthetic_data.py
python scripts\train_model.py --data data\synthetic\synthetic_biceps_curl.csv
```

For real data: `scripts\collect_data.py` -> `validate_dataset.py` -> `train_model.py --data data\raw` (see `ml/data/README.md`).

### 3. Mobile app (Android phone, development build)

```powershell
cd frontend
npm install
copy .env.example .env        # set EXPO_PUBLIC_API_URL=http://<your-PC-IPv4>:8000/api/v1
npx expo run:android          # builds and installs the development build (BLE needs this, not Expo Go)
npx expo start --dev-client   # later runs
```

### 4. Firmware

Arduino IDE -> install board package *esp32 by Espressif* and library *HX711 (Bogdan Necula)* ->
open `firmware/esp32_physioband/esp32_physioband.ino` -> board *ESP32 Dev Module* -> Upload ->
Serial Monitor 115200 -> `status`, `tare`, `cal <kg>`, `gyrocal`.

### 5. Try everything without hardware

```powershell
backend\.venv\Scripts\python.exe scripts\simulate_device.py --api http://localhost:8000/api/v1
```

## Deploying the backend to Render

`render.yaml` (repository root) is a Render Blueprint for the FastAPI backend.

1. Push the whole repository to GitHub (the backend needs `ml/src` and `ml/saved_models/biceps_curl_quality.pkl`).
   `backend/.env` is git-ignored and must not be pushed.
2. MongoDB Atlas -> Network Access -> add `0.0.0.0/0` (Render free instances have no fixed outbound IP).
3. Render dashboard -> **New -> Blueprint** -> select the repository -> Render reads `render.yaml`.
4. When asked, paste your `MONGODB_URI` (with the real password). `JWT_SECRET_KEY` is generated by Render.
5. After the deploy, open `https://<service-name>.onrender.com/health` (expect database connected, model available)
   and `https://<service-name>.onrender.com/docs`.
6. In `frontend/.env` set `EXPO_PUBLIC_API_URL=https://<service-name>.onrender.com/api/v1` and restart Expo.

Free instances sleep after ~15 min without traffic; the first request then takes up to about a minute.
Open `/health` a minute before a demonstration to wake the service.
